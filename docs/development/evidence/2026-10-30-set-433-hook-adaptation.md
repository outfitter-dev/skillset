## Follow-up qualification at the recorded baseline

Cursor's [third-party hook step mapping](https://cursor.com/docs/reference/third-party-hooks#hook-step-mapping) explicitly maps `UserPromptSubmit` to `beforeSubmitPrompt`. This supports the narrow D3 event adapter. It does not establish equivalent arbitrary command input, output, shell environment or runtime effects. No provider was executed.

A disposable Cursor-only build with an authored `status: Inspecting prompt` succeeded and omitted that field from the generated hook file. `explain --json` returned the generic degraded adaptive-hooks reason without identifying the omission. This is a confirmed reporting gap: definition and attachment status need specific omission evidence through the existing render-result contract. The classifier's `lossless-adaptive` name and the public hooks page's runtime-preservation claim exceed the structural checks currently performed. Qualify those claims separately from the documented event mapping.

Cursor's current [matcher configuration](https://cursor.com/docs/hooks#matcher-configuration) also describes matching `beforeSubmitPrompt` against `UserPromptSubmit`, while the registry labels that matcher ignored. The current rejection is conservative; correcting its explanation must not automatically broaden portable matcher support. Documentation evidence was accessed 2026-10-30. These findings remain open and are not repaired by the hook-binding guard.
