The only authored skill-local implementation subtree in the tracked search is contributor-only `.skillset/skills/skillset-adrs/scripts/`, ten TS implementations:

These are source-owned **D2 explicit documentation lifecycle changes**, not Claude/Codex/provider substitutions. Cross-reference regex operates on text globally with narrow filename patterns, so documentation edit correctness/fenced examples are a separate ADR-helper concern if requested; no provider runtime evidence is needed and no untested behavior is called D1.
- `lib/amendments.ts` validates ADR amendment/dependency relationships; `lib/decision-map.ts` derives and writes repo decision maps/index representations; `lib/index.ts` writes an ADR index. These are documentation-owned output/serialization, not Skillset adaptive-source provider rendering. `skillset-adrs/SKILL.md` authorizes these helpers as ADR operations; generated internal copies accompany that standalone skill. Public `plugins/skillset` has no such scripts, and public closure deliberately rejects routes to contributor-only helpers.

The two skill-local `__tests__` files are not executable payload implementations. No evidence suggests these scripts are registered as `@skillset/transforms` production lowerers. Their source and generated copies should still be synchronized by normal build checks, which is a separate property from D1 provider proof.
