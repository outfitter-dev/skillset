## Reproduced findings

1. **Claude plugin manifest nested maps: false acceptance against the project's own shared manifest contract.** `provider-format-conformance.ts:480-524` validates declared root types, author and experimental keys only. `claude-marketplace-inventories.ts:6-10` explicitly says the same manifest fields validate the same way inside both surfaces. Marketplace dispatch invokes `claude-format-conformance.ts:163-192,400-640,735-1012` and validates nested maps/arrays; standalone does not. Direct `checkProviderFormatConformance([{path:'plugins/a/.claude-plugin/plugin.json',content:encode(JSON.stringify({name:'a',description:'a',commands:{bad:42},mcpServers:{server:{command:99}},userConfig:{x:42}}))}])` returns `ok:true, issues:[]`. The same three fields in `{name:'x',owner:{name:'x'},plugins:[{name:'a',source:'./a',...fields}]}` at `.claude-plugin/marketplace.json` emit three `invalid-field-type` issues at `plugins[0].commands.bad`, `.mcpServers.server.command`, and `.userConfig.x`. The marketplace schema respectively requires object command values, string command, and object userConfig values. This demonstrates offline inconsistency and a marketplace-schema mismatch; standalone provider schema/runtime equivalence is not independently established by that marketplace schema. The shared validator must distinguish marketplace-only source, headers, identity, and extra rule references before reuse; existing marketplace path tests at `provider-format-conformance.test.ts:792-1058` cover nested cases, not a same-content paired standalone test.

2. **Agent Plugins author: schema-backed false acceptance.** `provider-format-conformance.ts:569-669` checks `author` only as object, unlike the Codex legacy / Cursor paths' `checkAuthorObject`. At `plugins/a/plugin.json`, `{ "$schema":"https://agent-plugins.org/schemas/1.0.0/plugin.schema.json", "name":"a", "version":"1.0.0", "author":{"name":42}, "extensions":{"com.openai":{"interface":{}}}}` returns `ok:true`. Full `listStandardProfileSchemaSnapshots('agent-plugins-1.0')` manifest schema states `author.properties.name/email/url` string and `additionalProperties:false`, with no author-name required. Thus do not blindly reuse `checkAuthorObject`, which requires name: empty object and email-only must remain valid according to this standard. Cover bad members/unknown keys and optional name, plus valid near cases. No evidence of byte loss or runtime acceptance.


3. **Cursor marketplace metadata.description: schema-backed false acceptance.** The exact Cursor authoring schema pin `1aae96a24c2796419933bc8bfe3a1255394e7199c35740b36325e0ce6dbc253d`, retained at `/tmp/set495-cursor-marketplace-schema.json`, defines metadata as an open object with an optional string `description`. `.cursor-plugin/marketplace.json` containing `{"name":"x","plugins":[],"metadata":{"description":42}}` returns `ok:true`. The correct bounded check validates that known member when present while preserving arbitrary metadata extension members; `{"description":"ok","any":{"x":42}}` is a valid nearby control. This is the authoring schema, not a claim about installed Cursor runtime.

4. **Codex 0.147.0 legacy interface member types: provider-source-backed false acceptance.** At `plugins/a/.codex-plugin/plugin.json`, `{"name":"a","interface":{"displayName":42,"capabilities":[42]}}` returns `ok:true`; pinned [legacy manifest source](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/core-plugins/src/manifest.rs) `RawPluginManifestInterface` has `Option<String>` displayName and `Vec<String>` capabilities/screenshots, and the legacy parse path deserializes that type. Nullable optional strings and defaultPrompt need separate treatment: `defaultPrompt` has explicit `Invalid(JsonValue)` variants and must not be treated as rejected merely because it is not a string or string array. This is static source evidence, not an executed provider probe. The overlay path supports uppercase URL aliases in addition to camelCase; follow that source rather than projecting Agent Plugins constraints onto it.
