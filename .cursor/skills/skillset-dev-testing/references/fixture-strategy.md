# Fixture And Conformance Strategy

## Fixture Tiers

| Tier | Use when | Location |
| --- | --- | --- |
| Inline temp fixture | A focused assertion can own a small source map | Beside the test under `apps/skillset/src/__tests__/` or a package test |
| Checked-in fake repo | A whole repository must be inspected, shared, or kept readable | `fixtures/<case>/` |
| Pinned external repo | Adoption fidelity needs evidence from a living upstream | `fixtures/external/repos.yaml` plus gitignored clones |

Checked-in fake repos use root `skillset.yaml` and canonical source under `.skillset/`. Keep `fixtures/kitchen-sink/` as the broad positive golden reference; add a separate fixture for lifecycle, feature-isolation, or negative cases.

## Git-Backed Fixtures

Create the parent with `createTestGitFixtureRoot()`, create a fresh child beneath it, and pass the parent as `disposableRoot` to `initializeTestGitRepository()` or `createTestGitRemote()`. The shared helper rejects symlinks, existing or bare repositories, linked worktrees, shared common directories, unrelated temp roots, and the Skillset checkout.

## Evidence Boundaries

- Compiler fixtures prove implementation behavior.
- Self-hosted dogfooding proves repository workflows through real commands and source.
- `skillset test` proves declared deterministic/runtime checks in isolated workspaces.
- Deterministic conformance compares generated bytes, locks, operation facts, and reports after narrow documented normalization.
- Adapter conformance compares produced render results with registry support claims.
- External conformance is an opt-in slow adoption lane.
- Evals judge model-facing effectiveness and may require provider harnesses, credentials, graders, or human review; they are not ordinary compiler tests.

Never claim provider runtime effectiveness from a green structural conformance check.
